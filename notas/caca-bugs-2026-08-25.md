## 1. [CRASH] CRASH: `-9223372036854775808 % -1` derruba a VM com SIGFPE (core dumped)

**Por que está errado:** INT64_MIN % -1 é overflow de `idiv` em x86-64: a CPU levanta #DE e o processo morre. A VM faz o `%` direto em int64 sem tratar esse único par. Reproduz também com variáveis (`a = -9223372036854775808; b = -1; post(a % b)`). O interp devolve 0, que é o resultado matemático correto. Qualquer programa que faça `x % y` com valores vindos de entrada pode matar o processo inteiro — não é erro capturável por try/catch, é queda do binário.

```ps
post(-9223372036854775808 % -1)
```

## 2. [CRASH] Interp: `yield` dentro de `try` vaza o sinal interno YieldSignal como InternalError

**Por que está errado:** A VM executa correto. O interpretador vaza o objeto interno `YieldSignal` do Python: `_exec_generator_stmt` (src/poolscript/interpreter.py:1968) trata WhileStmt/ForEachStmt/IfStmt caso a caso mas NÃO trata TryCatchStmt, então o try cai no ramo "statement normal" e o `yield` vira uma exceção Python que o `except Exception as exc` do try (interpreter.py:994) captura como se fosse erro do usuário. Resultado: o texto `YieldSignal: 1` é entregue ao usuário como se fosse a mensagem do erro dele, e o programa morre pedindo pra abrir issue no GitHub. Também acontece com `catch (YieldSignal e)` (t78) e com `try` sem erro nenhum.

```ps
action g():
    try:
        yield 1
        raise E("dentro")
    catch (e):
        post("gen pegou:", e)
        yield 99

for each v in g():
    post(v)
```

## 71. [DIVERGENCIA] null == false: True no interpretador, False na VM
